The backend will consist of:
1. Python API server
   FastAPI endpoints that the React frontend can call.
2. Stop-data validation
   Checks the depot and 3–10 stop coordinates sent from the frontend.
3. Reverse geocoding
   Converts a dragged pin’s latitude/longitude into a readable Mumbai address.
4. OSRM integration
   Gets real driving time and distance between every pair of stops.
5. Travel-time matrix builder
   Converts OSRM results into the matrix format required by the solver.
6. Google OR-Tools solver
   Finds the fastest visit order for all stops, starting and ending at the depot.
7. Road-route geometry
   Requests OSRM’s actual road path for the optimized order, so Leaflet can draw it.
8. API response formatter
   Returns optimized stops, total distance, estimated duration, addresses, and route coordinates to React.
9. Error handling and configuration
   Handles unavailable map services, invalid locations, and environment settings such as API URLs.

**Nominatim** is a search and geocoding service built using OpenStreetMap data.

It supports two main operations:

- **Forward geocoding:** address → coordinates
- **Reverse geocoding:** coordinates → readable address

In our app, we use reverse geocoding:

```text
latitude + longitude
        ↓
Nominatim
        ↓
street address, city, state, postcode
```

Example:

```http
GET https://nominatim.openstreetmap.org/reverse?lat=19.0619&lon=72.8995&format=jsonv2
```

It returns information such as:

```json
{
  "display_name": "Chembur East, Mumbai, Maharashtra, India",
  "address": {
    "suburb": "Chembur",
    "city": "Mumbai",
    "state": "Maharashtra",
    "country": "India"
  }
}
```

It is separate from OSRM:

- **Nominatim:** finds readable addresses
- **OSRM:** finds driving routes and travel times
- **OpenStreetMap tiles:** displays the map background
